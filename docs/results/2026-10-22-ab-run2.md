# A/B 第一次正式結果：Cairnwork 過濾 vs 裸跑（2026-10-22）

**結論：沒贏，兩組打平。** 28 題、單一模型，屬方向性結果（N < 30），不是確認性檢定。

## 我們測什麼

同一個 worker（同模型 gemini-3.8-flash-high、同一份提示）在各自的乾淨 clone 修同一批 Issue，各跑一次：

- **A0 裸跑**：worker 自報完成、diff 非空就交付。
- **A1 Cairnwork**：交付前由 Cairnwork 在隔離沙盒跑「延後測試」（worker 看不到；base 失敗、正確修正通過），核心公證（Core）判 VERIFIED 才交付。

評分用另一套 worker 與 Cairnwork 都看不到的 holdout（另寫的 F2P 變體＋全套件回歸比對），再由兩位盲審模型（Claude Sonnet、Codex）只看去識別化 diff 與 Issue，判「可直接合併／需修改／不可用」。**可採用**＝holdout 通過且兩位都判可直接合併（意見不一致算不可採用）。

判贏條件在開跑前凍結：① 交付精確率（可採用 ÷ 交付）A1 比 A0 高至少 25 個百分點，② 可採用數不少於 A0 減 1，③ 每個可採用修正分攤的審查成本 A1 ≤ A0。三項同時成立才算贏。

## 結果

| | A0 裸跑 | A1 Cairnwork |
|---|---|---|
| 交付 | 28 | 28（VERIFIED 28/28） |
| holdout 通過（含無回歸） | 22 | 23 |
| 可採用 | 12 | 12 |
| ① 交付精確率 | 42.9% | 42.9%（差 0，門檻 +25 → **未達**） |
| ② 可採用數不劣 | — | 成立 |
| ③ 每個可採用的審查成本 | 3.17 | 2.92（成立） |

題層級配對：兩組都可採用 11 題、都不可 15 題、各有 1 題只有一邊可採用。交付精確率差（A1 − A0）的 95% 配對 bootstrap 信賴區間為 −10.7 到 +10.7 個百分點（B = 10,000，固定種子），上限也遠低於 +25 的門檻。兩位盲審一致度 Cohen's kappa 0.50（一致率 77%）。

## 為什麼打平

- **這批題對這個模型太容易。** 真正沒修好的（holdout 的 F2P 變體失敗）只有裸跑 1 筆，Cairnwork 組 0 筆。延後驗收 28 筆全部通過，過濾一次都沒生效，所以兩組其實等於同一組。
- **不可採用的大宗是盲審判「需修改」**（改動範圍、風格、多餘變更），這不是測試驗收管得到的。
- **評分環境有一個副作用**：5 題兩組都只因同一個檢查「工作樹與 HEAD 一致」的測試被判回歸，判斷是評分程序造成、不是模型錯。依預註冊不回頭改分；不計這類回歸時是 14 比 15，結論不變。

- **事後補查（探索性，不改變判定）**：把裸跑組那筆唯一真失敗的 patch 拿去跑 Cairnwork 的延後測試，結果**通過**——也就是說，就算這筆出現在 Cairnwork 組，延後驗收也擋不下來。只有 1 個案例，估不出擋下率，但它顯示延後測試比評分用的 holdout 寬鬆。
- **審查成本 3.17 對 2.92 的差距不能歸功於過濾**：過濾一筆都沒擋，這個差距來自兩組各自生成的隨機差異。

所以本輪的結論是：**「交付前驗收能提高交付品質」這個主張沒有被證實**。本輪幾乎沒有需要擋的失敗，不足以判斷延後驗收攔截錯誤的能力；唯一的一個案例沒有攔下。

## 執行紀錄

- 預註冊 v1.0 開跑前凍結，另有三份補遺，都在看到評分結果前提出：worker 改走帳號池派發器；停滯門檻改為 900 秒、作廢門檻不同的第一次執行；盲化檢查誤判題目原有檔名的修正。
- 56 列全數完成；1 列帳號池環境失敗（模型未執行）依預註冊規則重做。
- 沒有任何 patch 改到測試檔或允許範圍外的檔案。

## 下一步

開新一輪前已請兩位獨立模型議員（Codex、Gemini）審查設計，兩位的主要建議一致，新一輪預計：

- **改成同一份 patch 評兩種政策**：每題只讓 worker 產生一份 patch，再分別看「直接交付」與「驗收通過才交付」的結果；被擋下的 patch 也照樣評分，才能量到誤擋。
- **主指標改為機制指標**：錯誤擋下率（holdout 失敗的 patch 中被擋下的比例）與可採用誤擋率（好 patch 被誤擋的比例），兩項同時達標才算機制成立；原本的交付精確率保留為產品指標、分開報告。
- **篩出模型真的會失敗的題**：用正式模型每題乾跑多次、用獨立的篩選測試判難度，選題時不看延後驗收的結果；另留一組未篩選的隨機題分開報告。
- **延後測試與 holdout 由不同作者撰寫**，避免共同盲點；評分環境先用參考解與已知錯誤解校準。
- **維持純過濾**：失敗重試、範圍檢查等改善修補品質的機制另開實驗，不混進這一輪。

新一輪一樣先預註冊再開跑，結果不論輸贏都公開。
